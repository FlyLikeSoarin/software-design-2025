## Описание диаграммы (Flowchart)

Диаграмма показывает **архитектуру системы управления дефектами и ремонтом** на производстве: клиентские веб-приложения → API Gateway → набор микросервисов → хранилища/шина событий → внешние интеграции завода (ERP/MES, PLC, SSO, email).

---

### 1. Клиентские приложения (UIs)

- **Диспетчерское веб-приложение** - работа с распределением авто и очередями ремонта.
- **ОТК / QC веб-приложение** - фиксация результатов проверок и дефектов.
- **Бригадир / ремонтник UI** - назначение задач и выполнение ремонта.
- **Админка зон / бригад** - управление справочниками зон/мест ремонта и бригад.

Все UI взаимодействуют с сервером по **HTTPS**.

---

### 2. API Gateway

Единая входная точка: **HTTPS • Auth • Rate-limit**.

- Принимает запросы от UI.
- Маршрутизирует их в нужные микросервисы.
- Использует **Auth Service** для аутентификации и авторизации.

---

### 3. Core backend (микросервисы)

- **Auth Service** - JWT, RBAC, интеграция с **SSO (IdP)**.
- **Defect Service** - учёт дефектов.
- **Repair Service** - назначения и ремонты (ремонтные задачи).
- **Zone Service** - зоны и места ремонта.
- **Crew Service** - бригады и доступность сотрудников.
- **QC Service** - проверки и результаты испытаний.
- **Dispatch Service** - диспетчеризация (очереди/распределение по зонам).
- **Reporting Service** - отчёты и аналитика.
- **Notification Service** - уведомления.

---

### 4. Хранилища и инфраструктура (DATA)

- **PostgreSQL** - основная транзакционная БД.
- **Message Bus** - шина событий (асинхронная интеграция/реакции на события).
- **Redis** - кэш и оперативные состояния (используется диспетчеризацией).
- **Object Storage** - хранение файлов (выгрузки/отчёты).
- **OLAP / MatViews** - аналитический контур (агрегации/отчётность).

Связи по диаграмме:

- `Defect / Repair / QC → PostgreSQL + Message Bus`
- `Dispatch → Redis`
- `Reporting → OLAP + Object Storage`
- `Zones / Crew → PostgreSQL`

---

### 5. Внешние интеграции завода (EXT)

- **ERP/MES → Defect & Repair** - производственные данные/заказы/события.
- **Конвейер / PLC события → Defect & QC** - события линии и контроля.
- **IdP / SSO ↔ Auth Service** - единая аутентификация.
- **Email сервер (SMTP) ← Notification Service** - отправка уведомлений.

---

### Итоговая логика

Пользователь работает в одном из UI → запрос идёт через **API Gateway** → выполняется в профильном микросервисе → данные сохраняются в **PostgreSQL**, при необходимости публикуются события в **Message Bus**, оперативные статусы хранятся в **Redis**, отчёты формируются в **OLAP** и/или сохраняются в **Object Storage**, уведомления отправляются через **SMTP**, а заводские системы (**MES/PLC**) могут инициировать обновления дефектов/ремонтов/проверок.
